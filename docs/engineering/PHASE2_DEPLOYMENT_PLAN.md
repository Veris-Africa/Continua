# Phase 2 deployment plan

Phase 1 is live and verified; Phase 2 is local and must not be pushed or deployed automatically. Application and SQL releases are separate. Current settings must remain unchanged while reviewing.

1. Review local commits, route matrix, test results and all three SQL files. Preserve Phase 1 caching, rights, bounded queries, instrumentation and manifest. Resolve policy questions in security results without silently changing public contracts.
2. Restore a current sanitized schema/ACL snapshot into an isolated branch, including all reviewed SECURITY DEFINER bodies, policies and triggers. The local fixture uses simplified surrounding tables and cannot replace this production-schema rehearsal. Run owner/Free/Premium/Plus, registration/session/logout/recovery, profile editing, portfolio, watchlist, community, payment mock and source-rights tests there. Never use real payment credentials for initiation tests.
3. Obtain separate explicit approval for production SQL: phase2-application-privileges.sql and phase2-watchlist-integrity.sql, and optionally phase2-hosted-checkout-intents.sql. Approval must name the production project/branch, files and maintenance window. Do not run application-grants.sql wholesale on production.
4. Immediately before approved SQL, run phase2-preflight-readonly.sql; privately capture exact ACLs, function definitions/search paths, triggers, constraints and conflict aggregates. Include column ACLs and role memberships. Confirm backup/PITR availability and a tested restore path; do not assume Free-plan retention. Prepare exact inverse function/ACL statements from this snapshot and review them. Abort on drift, duplicates, cross-owner relationships, inherited admin grants, untrusted public-schema CREATE or service EXECUTE dependency.
5. Rehearse narrow SQL one file/transaction at a time. Watchlist validation/index creation takes locks; keep the supplied lock and statement timeouts, use a low-traffic window and abort rather than extend blindly. No deletion/merge/backfill is authorized. Check old and new app compatibility against resulting schema. E01 changes must preserve DML, provisioning, trigger firing and signed-payment fulfillment.
6. Only after review, obtain approval to push Phase 2 to main and allow Cloudflare/Render application deployment. Deploy backend before frontend because the new default-watchlist RPC and holding version contract must be available. Old cached clients without holding versions will receive a safe refresh conflict, not silently overwrite data. Verify live SHA/build manifest, health and managed Auth pin. Do not cut over to Go/Python candidate services.
7. Hosted checkout: keep PAYSTACK_CHECKOUT_INTENTS_ENABLED=false until its additive ledger DDL and hosted caller intent/recovery support are separately verified and approved. Enabling it is a production environment change requiring approval/restart. Current native checkout is preserved. Unknown initialization references need verification/provider reconciliation, never automatic reinitialization.
8. Keep ENGINE_PAID_AI_ENABLED=false (or unset) and do not provision/copy keys. The new default masks an existing key unless explicitly approved. No paid activation, Upstash creation/shared-store activation, environment changes or account resets are part of this release. If a paid key is currently used, that behavior change must be reviewed explicitly before deployment.
9. Post-release bounded smoke checks: existing login/logout, capability accuracy, same/cross-owner access in staging only, watchlist default once, normal portfolio edit/stale conflict, one real user's read-only app views. Review 401/403/503 and SQL error rates. Do not run destructive fixtures against production or make test charges. Recheck ingestion flags unchanged.

Required approvals: production SQL/grants (separate files), Phase 2 GitHub main push/application rollout, optional hosted-intent flag activation after compatibility checks. Paid AI and any new infrastructure remain separately prohibited unless explicitly approved. No production customer-data mutation is requested.
